## 1. 进程与线程

进程是程序的一次执行实例，也是资源分配和保护的基本单位。不同进程通常有相对独立的虚拟地址空间。

线程是进程内的执行流，也是操作系统调度的基本单位之一。一个进程至少有一个线程。

### 同进程线程共享

- 代码段
- 全局变量和静态数据
- 堆内存
- 打开的文件描述符
- 大部分进程级资源

### 每个线程独享

- 程序计数器
- 寄存器上下文
- 线程栈
- 线程局部存储
- 线程 ID

共享内存使线程通信方便，但也带来竞态条件和线程安全问题。

## 2. 进程间通信

进程地址空间相对隔离，普通 Python 变量不能像同进程线程那样直接共享。常见 IPC：

- 管道
- 消息队列
- 共享内存
- Socket
- 信号
- 数据库或外部消息系统

具体选择取决于数据量、延迟、可靠性和跨机器需求。

## 3. 死锁

死锁是多个执行单元互相持有资源并等待对方释放，导致都无法继续推进的状态。

### 四个必要条件

1. 互斥：资源同一时刻只能被一个执行单元占有。
2. 占有且等待：已经持有至少一个资源，同时等待其他资源。
3. 不可剥夺：资源不能被强制夺走，只能由持有者主动释放。
4. 循环等待：存在资源等待环。

示例：

```text
线程 A：持有 lock_1，等待 lock_2
线程 B：持有 lock_2，等待 lock_1
```

### 避免和降低风险

- 所有线程统一加锁顺序。
- 减少多锁嵌套。
- 缩小临界区和锁持有时间。
- 获取锁设置超时，失败后回退或重试。
- 使用 `with lock:` 确保异常时释放。
- 优先使用队列、消息传递等更高层并发工具。

协程也可能发生逻辑死锁，例如协程互相等待永远不会完成的 Future/Lock；“使用协程”不等于自动消灭死锁。

## 易错点

1. “资源有限”不是死锁四个必要条件中的标准项。
2. 有 GIL 不等于没有线程竞态或死锁。
3. 线程共享堆，但每个线程有自己的栈和寄存器上下文。
4. 进程隔离比线程强，但 IPC 和切换开销更高。

## 面试表达

进程拥有相对独立的地址空间，强调资源隔离；线程是进程内的执行单元，共享代码、堆和文件等资源，但独享栈、寄存器和程序计数器。死锁发生必须同时满足互斥、占有且等待、不可剥夺和循环等待，工程中常通过统一加锁顺序、缩小临界区、超时和减少锁嵌套来避免。

## AI 应用开发关联

- 多请求共享缓存或连接时要处理竞态和锁。
- 工具执行和文档处理可放独立进程降低故障影响。
- 多 Agent 或多工具任务如果互相等待资源，也可能形成逻辑死锁。
