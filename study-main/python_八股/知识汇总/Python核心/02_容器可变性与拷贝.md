## 1. list 与 tuple

| 对比项 | list | tuple |
|---|---|---|
| 可变性 | 可增删改 | 创建后不能改变元素绑定 |
| 语法 | `[1, 2]` | `(1, 2)` |
| 哈希 | 不可哈希 | 所有元素可哈希时才可哈希 |
| 典型用途 | 动态消息、检索结果、文档切片 | 固定的小型结构、坐标、多返回值 |
| CPython 内存特点 | 通常为扩容保留额外空间 | 通常更紧凑 |

不要把“tuple 一定更快”当成 Python 语言保证。性能取决于实现、操作和数据规模。

### tuple 的不可变性是浅层的

```python
t = ([1, 2], 3)
t[0].append(4)
print(t)  # ([1, 2, 4], 3)
```

不能让 `t[0]` 重新绑定到另一对象，但 `t[0]` 指向的列表本身仍可修改。

### tuple 可哈希条件

```python
hash((1, 2))       # 可以
hash((1, [2, 3]))  # TypeError
```

一个 tuple 只有在其所有元素都可哈希时才可哈希。

## 2. 赋值、浅拷贝与深拷贝

### 普通赋值

```python
a = [[1, 2]]
b = a
```

没有创建新容器，`a is b` 为 `True`。

### 浅拷贝

浅拷贝创建新的最外层容器，但内部元素引用仍可能共享。

```python
import copy

a = [[1, 2]]
b = copy.copy(a)

print(a is b)       # False
print(a[0] is b[0]) # True
```

修改内部共享对象会互相影响：

```python
b[0].append(3)
print(a)  # [[1, 2, 3]]
```

修改外层结构通常互不影响：

```python
b.append([9])
print(a)  # 仍只有一个内部列表
```

### 深拷贝

深拷贝递归复制嵌套对象，使复制结果尽量独立。

```python
c = copy.deepcopy(a)
print(a[0] is c[0])  # False
```

深拷贝通常更耗时、更占内存；涉及循环引用、外部资源、锁、文件句柄等对象时，还要具体分析，不能无脑使用。

## 易错点

1. 错误：“浅拷贝等于两个变量指向同一对象。”
   - 这是普通赋值；浅拷贝的外层对象不同。
2. 错误：“tuple 里面所有内容都不可变。”
   - tuple 不能改变元素绑定，但元素指向的可变对象仍能修改。
3. 错误：“tuple 总能当字典键。”
   - 所有元素都可哈希时才可以。
4. 错误：“深拷贝永远是最安全的选择。”
   - 它有性能、语义和外部资源边界。

## 面试表达

浅拷贝创建新的外层容器，但内部嵌套对象仍共享引用；深拷贝会递归复制嵌套对象。list 是可变动态序列，tuple 是不可变序列；tuple 只有所有元素都可哈希时才能作为字典键。tuple 的不可变性是浅层的，内部可变对象仍可被修改。

## AI 应用开发关联

- 复制 Agent state、消息历史或请求配置时，要明确是否需要隔离嵌套对象。
- Pydantic 模型、数据类或明确的不可变配置通常比裸 tuple 更适合复杂 API 数据。
- 深拷贝大型文档块或检索结果可能造成明显内存开销。
