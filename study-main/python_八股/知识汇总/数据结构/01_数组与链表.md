## 1. 数组为什么支持 O(1) 随机访问

数组通常连续存储，并且同一数组的元素大小固定。已知首地址、元素大小和下标 `i`，可以直接计算地址：

```text
address(array[i]) = base_address + i * element_size
```

计算次数不随数组长度增长，所以按下标访问为 `O(1)`。

## 2. 链表为什么是 O(n) 随机访问

链表结点不要求连续存储。单链表结点只知道下一个结点的位置。访问第 `i` 个结点时，需要从头结点沿 `next` 走若干次；最坏走到尾部，因此为 `O(n)`。

更严谨的说法不是“每次都遍历全部”，而是找到目标即可停止，最坏情况下才接近完整遍历。

## 3. 操作复杂度对比

| 操作 | 数组/顺序表 | 单链表 |
|---|---|---|
| 按下标访问 | O(1) | O(n) |
| 查找某个值 | O(n) | O(n) |
| 尾部追加 | 动态数组均摊 O(1) | 有尾指针时 O(1) |
| 已知位置后插入 | 通常 O(n)，需要移动 | 已知结点时 O(1) |
| 删除已知位置 | 通常 O(n)，需要移动 | 已知前驱时 O(1) |

复杂度必须明确前提。例如“链表插入 O(1)”要求已经拿到目标结点或前驱；如果先查找插入位置，总复杂度仍可能是 O(n)。

## 4. 工程差异

- 数组连续内存通常具有更好的空间局部性，CPU Cache 更友好。
- 链表需要额外指针空间，结点分散会产生更多间接访问。
- 链表理论插入快，不代表真实工程性能一定比数组好；还要考虑查找、分配和缓存局部性。

## 易错点

1. “链表访问必须遍历整个链表”不严谨，找到目标即可停止。
2. “链表插入永远 O(1)”缺少已知位置的前提。
3. Python `list` 是动态数组思路，不是链表。

## 面试表达

数组连续存储，可以根据首地址、元素大小和下标直接计算元素地址，所以随机访问是 O(1)。链表结点分散存储，只能从头沿指针逐个定位，最坏为 O(n)。数组中间插入需要移动元素，链表在已知前驱时修改指针即可，但查找位置仍可能是 O(n)。

## AI 应用开发关联

对 embedding 和批量数值计算，连续数组通常更有利于缓存和向量化。对话消息等动态序列在 Python 中通常使用 list，而不是手写链表。
