## 第 1 题：Python 变量与对象

### 题目

Python 中的变量保存的是对象本身，还是对象的引用？请简单说明变量赋值时发生了什么。

### 我的答案

什么是变量保存??? 是变量的引用,变量赋值会先在内存分配空间,然后将变量指向这个空间

### 标准答案与分析

你在答案中提出的“什么是变量保存？”需要先明确回答：Python 变量名通常不是保存对象内容的容器，而是保存/记录一个到对象的绑定关系。面试中常说“变量保存的是对象引用”，是为了说明变量名可以指向对象；更严谨的语言是“变量名绑定到对象”。

你的方向“变量是对象的引用”基本正确，但“赋值会先在内存分配空间”不准确。赋值不一定都会新分配对象：如果右侧对象已经存在，可能只是增加或改变一个名称绑定。

Python 中一切数据都是对象。变量名不是一个固定的“内存盒子”，而是绑定到对象的名称。赋值时，Python 通常先计算右侧表达式得到对象，再让左侧变量名绑定到这个对象。

```python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]
```

这里 `a` 和 `b` 是两个变量名，但绑定到了同一个列表对象。`b.append(3)` 修改的是列表对象，所以通过 `a` 也能看到变化。

```python
a = [1, 2]
b = a
b = [3, 4]
print(a)  # [1, 2]
print(b)  # [3, 4]
```

这里是 `b` 重新绑定到新列表，并没有修改 `a` 原来绑定的对象。

面试标准表达：Python 变量本质上是指向对象的名称绑定，而不是存放对象值的固定内存盒子。赋值时先计算右侧表达式，再把左侧名称绑定到结果对象。多个变量可以绑定同一个可变对象；修改对象可能被其他变量观察到，但重新赋值只是改变绑定关系。

### 面试追问

Python 是值传递还是引用传递？

更准确的说法是“对象引用的传递”或“按共享对象传递”。
函数接收的是对象引用的副本：函数内部修改可变对象，外部可能看到；
如果函数内部让参数重新绑定到另一个对象，外部变量不会改变。

```python
def change(items):
    items.append(1)  # 修改原对象，外部可见

def rebind(items):
    items = [9, 9]   # 只改变局部绑定，外部不可见
```

## 第 2 题：`is` 与 `==`

### 题目

`is` 和 `==` 有什么区别？下面代码的两个输出分别是什么？为什么？

```python
a = [1, 2]
b = [1, 2]

print(a == b)
print(a is b)
```

### 我的答案

不一样，`is` 比较的是内存地址，`==` 比较的是内存里面的变量值。

### 标准答案与分析

你的方向基本正确，但面试中需要更严谨：

- `is` 比较对象身份，判断两个变量是否绑定到同一个对象。
- `==` 比较对象相等性，通常会调用对象的 `__eq__()` 方法。

输出是：

```text
True
False
```

`a` 和 `b` 是两个内容相同但分别创建的列表，因此 `a == b` 为 `True`，而 `a is b` 为 `False`。

不要简单把 `is` 定义成“比较内存地址”。在 CPython 中对象身份通常和地址有关，但 Python 语言层面更准确的概念是 identity，也就是对象身份。

判断 `None` 时应使用：

```python
if value is None:
    ...
```

判断值是否相等时使用 `==`。不要使用 `is` 判断整数或字符串的值是否相等，因为解释器可能对它们进行缓存或驻留。

## 第 3 题：可变默认参数

### 题目

下面函数连续调用两次会输出什么？为什么？应当如何修改？

```python
def add(value, items=[]):
    items.append(value)
    return items

print(add(1))
print(add(2))
```

### 我的答案

会分别输出 `[1]`、`[2]`，因为 `items` 是局部变量，然后每次调用都是空列表，所以每次都是重新分配。

### 标准答案与分析

你的结论和原因都错误。实际输出是：

```text
[1]
[1, 2]
```

Python 函数的默认参数在函数定义时求值一次，而不是每次调用时重新求值。这里的空列表只创建一次，之后多次调用会共享这个列表。

可以近似理解为：

```python
_default_items = []  # 函数定义时创建一次
add(1, _default_items)  # [1]
add(2, _default_items)  # [1, 2]
```

正确写法是使用 `None` 作为哨兵值：

```python
def add(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items
```

面试标准表达：Python 默认参数在函数定义阶段求值。可变对象作为默认参数会导致多次调用之间共享状态，容易造成数据污染。通常使用 `None` 作为默认值，在函数体内部创建新的列表或字典。

## 第 4 题：浅拷贝与深拷贝

### 题目

浅拷贝和深拷贝有什么区别？对于嵌套列表，复制后修改内部列表时，两种拷贝分别会发生什么？

### 我的答案

浅拷贝：变量拷贝，不同的变量指向同一个内存地址；深拷贝：新建内存地址，赋值给变量。

浅拷贝：内部列表会被修改，所以所有指向该地址的变量名的内容都会修改。

深拷贝：不同变量名会指向不同的地址，所以单个变量修改时只会修改自己的列表。

### 标准答案与分析

你掌握了“浅拷贝的内部对象可能共享”和“深拷贝相互隔离”的方向，但浅拷贝的定义不准确。

浅拷贝会创建新的最外层容器，但只复制内部元素的引用；深拷贝会递归复制嵌套对象。

```python
import copy

original = [[1, 2], [3, 4]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

print(original is shallow)        # False，外层列表不同
print(original[0] is shallow[0])  # True，内部列表相同
print(original[0] is deep[0])     # False，内部列表也不同
```

因此：

```python
shallow[0].append(99)
print(original)  # [[1, 2, 99], [3, 4]]
```

但是：

```python
shallow.append([5, 6])
print(original)  # 不会新增 [5, 6]
```

因为两个对象的最外层列表不同。

深拷贝会递归复制嵌套对象，因此修改 `deep[0]` 不会影响 `original[0]`。但深拷贝更耗时、更耗内存，循环引用或不可复制对象还可能需要额外处理。

常见写法：

```python
shallow = original.copy()
shallow = original[:]
shallow = copy.copy(original)
deep = copy.deepcopy(original)
```

## 第 5 题：`list` 与 `tuple`

### 题目

Python 的 `list` 和 `tuple` 有什么区别？请从内存、性能、哈希和使用场景等方面说明。

### 我的答案

`list` 是列表，`tuple` 是元组，然后就不知道了。

### 标准答案与分析

| 对比项 | list | tuple |
|---|---|---|
| 可变性 | 可变，可以增删改 | 不可变，创建后不能修改元素绑定 |
| 语法 | `[1, 2]` | `(1, 2)` |
| 典型用途 | 动态数据、追加、删除、排序 | 固定结构记录、坐标、多个返回值 |
| 哈希 | 不可哈希，不能作为字典键 | 所有元素可哈希时才可哈希 |
| 内存/性能 | 通常为动态扩容保留额外空间；具体性能取决于实现和操作 | 在 CPython 中通常更紧凑；不要把“tuple 一定更快”当成语言保证 |

```python
hash((1, 2))       # 可以
hash((1, [2, 3]))  # TypeError，因为内部 list 不可哈希
```

tuple 的不可变性不是递归的：

```python
t = ([1, 2], 3)
t[0].append(4)
print(t)  # ([1, 2, 4], 3)
```

AI 应用中，持续追加对话消息、文档切片和检索结果通常使用 list；固定坐标或固定格式的小型记录可以使用 tuple；复杂结构更建议使用数据类或 Pydantic 模型。

面试标准表达：list 是可变的动态序列，适合需要修改的数据；tuple 是不可变序列，适合表示固定结构。tuple 当且仅当所有元素都可哈希时，才能作为字典键或集合元素。

## 第 6 题：数组与链表的随机访问

### 题目

数组随机访问为什么是 `O(1)`？链表随机访问为什么是 `O(n)`？

### 我的答案

因为数组是一个变量指向一个地址空间，空间是连续的，所以可以直接按照地址访问；链表的地址空间是随机的，只能按照指针来访问，所以需要全部遍历。

### 标准答案与分析

你的核心方向正确，评分约 8/10。

数组通常连续存储，已知首地址、元素大小和下标 `i` 后，可以直接计算元素地址：

```text
address(array[i]) = base_address + i * element_size
```

因此随机访问是 `O(1)`。

链表结点不要求连续存储。访问第 `i` 个结点时，通常需要从头结点开始，沿着 `next` 指针走 `i` 次，所以随机访问平均/最坏复杂度为 `O(n)`。更严谨地说，不一定要“全部遍历”，找到目标结点后即可停止，最坏情况才需要走到尾部。

补充：数组中间插入或删除通常为 `O(n)`；单链表在已知插入位置结点时，插入可以是 `O(1)`，但查找该位置通常仍需要 `O(n)`。

## 第 7 题：进程、线程与协程

### 题目

进程和线程有什么区别？同一进程中的线程共享哪些资源？每个线程又独享哪些资源？请同时说明协程。

### 我的答案

把协程也加上；进程是分配资源的最小单位，一个进程会包含多个线程，剩下就不知道了。

### 标准答案与分析

你说“进程是资源分配的最小单位”基本正确，但需要完整掌握三者。

进程是程序的一次执行实例，通常拥有独立的虚拟地址空间、代码段、数据段、堆、文件描述符表等资源。进程之间默认隔离，进程通信需要管道、消息队列、共享内存、Socket 等机制。

线程是进程中的执行流，也是 CPU 调度的基本单位之一。同一进程中的线程共享：

- 代码段
- 全局变量和静态数据
- 堆内存
- 打开的文件描述符
- 大多数进程级资源

每个线程独享：

- 程序计数器
- 寄存器上下文
- 栈空间
- 线程局部存储
- 线程 ID

协程是用户态的轻量任务，通常由事件循环调度。在 `await` 处主动让出执行权，使事件循环运行其他任务。协程特别适合高并发 I/O，例如同时请求多个 LLM API、向量数据库、权限服务以及处理 SSE 流式连接。

| 项目 | 进程 | 线程 | 协程 |
|---|---|---|---|
| 调度者 | 操作系统 | 操作系统 | 用户态运行时/事件循环 |
| 隔离性 | 强 | 弱，同进程共享资源 | 通常共享所属线程资源 |
| 创建/切换开销 | 较大 | 中等 | 通常较小 |
| 典型场景 | 隔离、CPU 密集 | I/O、阻塞库 | 高并发 I/O |
| 并行能力 | 可利用多核 | CPython CPU 字节码受 GIL 影响 | 通常是单线程并发，不等于并行 |

AI 应用开发中的选择：并发请求模型和工具通常优先协程；只有同步接口的 SDK 可以放入线程池；图片处理、批量 embedding 等 CPU 密集任务通常考虑多进程或独立任务队列。

## 第 8 题：死锁

### 题目

什么是死锁？产生死锁必须同时满足哪四个必要条件？

### 我的答案

死锁是每个节点包含各自的资源，在请求其他的资源，然后循环等待；资源有限，循环等待。

### 标准答案与分析

你说出了互相等待和循环等待现象，但四个必要条件不完整。“资源有限”是背景描述，不是教材中要求回答的四个条件之一。

四个必要条件必须同时满足：

1. 互斥条件：资源同一时刻只能被一个进程或线程占用。
2. 占有且等待：已经占有至少一个资源，同时等待其他资源。
3. 不可剥夺条件：资源不能被强制从占有者手中夺走，只能由占有者主动释放。
4. 循环等待条件：存在等待环，例如线程 A 等 B 的锁，B 等 A 的锁。

Python 中可能出现这样的锁顺序问题：线程 1 先获取 `lock_a` 再获取 `lock_b`，线程 2 先获取 `lock_b` 再获取 `lock_a`。

避免死锁的方法包括：统一加锁顺序、缩小临界区、减少锁嵌套、获取锁设置超时、使用 `with lock:` 确保异常时释放锁。

面试标准表达：死锁是多个执行单元互相持有资源并等待对方释放，导致所有相关执行单元都无法继续。产生死锁必须同时满足互斥、占有且等待、不可剥夺、循环等待四个条件。

## 第 9 题：TCP 三次握手

### 题目

TCP 为什么需要三次握手？如果只使用两次握手，可能出现什么问题？

### 我的答案

不懂 TCP。

### 标准答案与分析

TCP 是面向连接、可靠传输、字节流的传输层协议。三次握手流程如下：

![alt text](img_v3_0214n_55bb7033-e469-4ea0-8253-da886819929g.jpg)

![alt text](img_v3_0214n_5bc0da0f-da49-42fa-b0e6-c68c0c653ccg.jpg)
```text
客户端                                服务端
  | -------- SYN, seq=x ------------> |
  | <----- SYN+ACK, seq=y, ack=x+1 -- |
  | -------- ACK, ack=y+1 ----------> |
```

第一步，客户端发送 SYN，表示希望建立连接，并发送客户端初始序列号 `x`。

第二步，服务端返回 SYN+ACK：SYN 表示服务端也同意建立连接并发送服务端初始序列号 `y`；ACK 表示服务端已收到客户端 SYN，确认号为 `x+1`。

第三步，客户端发送 ACK，确认号为 `y+1`，表示客户端已收到服务端 SYN。此时双方都确认了对方的发送和接收能力，连接可以使用。

如果只有两次握手，服务端无法确认客户端是否成功收到自己的 SYN+ACK。典型问题是客户端发送的旧 SYN 因网络延迟到达服务端，服务端误以为客户端发起新连接。如果两次握手就建立连接，服务端可能为实际上已经失效的请求分配资源，造成资源浪费。

面试标准表达：TCP 三次握手用于建立连接、同步双方初始序列号，并确认双方的发送和接收能力。两次握手无法让服务端确认客户端收到了自己的响应，旧 SYN 延迟到达时还可能导致服务端错误建立无效连接并占用资源。

AI 应用开发关联：FastAPI 等后端请求、HTTPS 和 SSE 流式连接都依赖底层 TCP；HTTPS 还会在 TCP 连接建立之后进行 TLS 握手。

## 第 10 题：Cache 与局部性原理

### 题目

Cache 为什么能够提高程序运行速度？它利用了程序的哪两种局部性？请分别解释。

### 我的答案

Cache 是把一些内容存储到小的、运行速度快的内存中；局部性和……

### 标准答案与分析

你的 Cache 方向正确，但遗漏了两种局部性和访问过程。

Cache 位于 CPU 和主存之间，容量较小但速度更快，用于保存近期可能再次访问的数据和指令。CPU 访问时先查 Cache：命中则快速返回；未命中则从更低层级存储读取，并可能把数据装入 Cache。现代 CPU 通常有 L1、L2、L3 多级 Cache。

它利用两种局部性：

1. 时间局部性：如果某个数据或指令刚刚被访问，那么它在不久后很可能再次被访问。
2. 空间局部性：如果某个地址被访问，那么它附近的地址很可能在不久后被访问。

```python
# 时间局部性：反复访问同一个变量
for _ in range(1000000):
    total += value

# 空间局部性：连续访问数组元素
for x in array:
    total += x
```

AI 应用开发中，批量 embedding、矩阵计算和连续数组通常更有利于 CPU Cache；大量 Python 对象和指针间接访问可能不如 NumPy 连续数组友好。

面试标准表达：Cache 利用程序访问的局部性，把近期使用或附近的数据和指令保存在比主存更快的存储中，以减少 CPU 访问主存的次数。时间局部性指近期访问的数据可能很快再次访问；空间局部性指当前访问地址附近的数据可能很快被访问。
